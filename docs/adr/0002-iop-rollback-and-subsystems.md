# IOP Subsystem Rollback Contract: Forward Audio, Native Input, Cached Disc

**Status: accepted, revised 2026-11-23.** The first version (2026-11-21) relied on emulated sound modules that could not make sound: the SPU2 was not emulated. Native input was not carried out as described: `scePadRead` read the keyboard whenever the game called it and gave both ports the same buttons. See [ticket 17](../wayfinder/base-to-playable-fight/tickets/17-iop-approach.md).

_PT-BR: **Situação: aceita, revisada em 23/11/2026.** A primeira versão (21/11/2026) contava com módulos de som emulados que não tinham como gerar som: o SPU2 não era emulado. O controle nativo não tinha sido implementado como descrito: o `scePadRead` lia o teclado a cada chamada do jogo e dava os mesmos botões às duas portas. Ver o ticket 17._

The original sound modules (`LIBSD`, `SDRDRV`, `CRI_ADXI`) run on the emulated IOP, on the game thread, over a PCSX2-matched SPU2 taken as a single piece from the PS2Recomp-Fixer fork into our PS2Recomp fork. The SPU2 advances by emulated IOP cycles only; the host plays its output from a one-way queue. Audio and the IOP stay outside the rollback state and run forward only. Controller input and the memory card are native on the EE side: the runtime takes one snapshot of both controller ports per frame at the frame boundary, every `scePadRead` in that frame returns it, and the memory card writes into host folders; `SIO2MAN`, `PADMAN`, `MCMAN` and `MCSERV` are not loaded. Disc reads are served from the extracted files without blocking a simulated frame.

_PT-BR: Os módulos de som originais (`LIBSD`, `SDRDRV`, `CRI_ADXI`) rodam no IOP emulado, na thread do jogo, sobre um SPU2 conferido com o PCSX2, trazido como peça única do fork PS2Recomp-Fixer para o nosso fork do PS2Recomp. O SPU2 só avança pelos ciclos emulados do IOP; o PC toca a saída a partir de uma fila de mão única. O áudio e o IOP ficam fora do estado do rollback e só andam para frente. Controle e memory card são nativos do lado da EE: o runtime tira uma foto das duas portas do controle por quadro, na fronteira do quadro, todo `scePadRead` daquele quadro devolve essa foto, e o memory card grava em pastas do PC; `SIO2MAN`, `PADMAN`, `MCMAN` e `MCSERV` não são carregados. As leituras de disco vêm dos arquivos extraídos, sem travar um quadro simulado._
